## NETWORKING NOTES

### Локальный запуск через 127.0.0.1

Для локального запуска необходимо вручную запускать каждый сервис с помощью poetry run с указанием портов. Это неудобно, т.к. каждый раз приходится прописывать длинную команду и помнить какой сервис работает на каком порту.

### Неудачный запуск контейнера с 127.0.0.1

Неудача при запуске происходит из-за того, что адрес 127.0.0.1 внутри контейнера указывает на сам этот контейнер, а не на основную операционную систему.

### Успешное взаимодействие контейнеров через имена сервисов

В среде Docker Compose создается общая виртуальная сеть. Вместо использования IP-адресов, контейнеры могут обращаться друг к другу по именам сервисов, указанным в docker-compose.yml

### Взаимодействие через хост (host.docker.internal)

Если сервис запущен в контейнере, но ему нужно достучаться до приложения, работающего напрямую на основной ОС (вне Docker), используется специальный адрес host.docker.internal.
