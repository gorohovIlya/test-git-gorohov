Структура проекта
```text
├── README.md	# Детальный технический отчет (статья по заданиям 1-5)
├── script.py
├── testing
│   ├── principle
│   │   ├── setup.py
│   │   ├── src
│   │   │   └── math_demo.py
│   │   └── tests
│   │       └── test_principle.py
│   └── tdd
│       ├── docs
│       │   └── TASK.md
│       ├── Makefile
│       ├── requirements.txt	# Список внешних зависимостей
│       ├── script.sh
│       ├── setup.py
│       ├── src 		# Исходный код приложения
│       │   ├── calc.py		# Модуль для проверки типов (Задание 3) 
│       │   ├── example.py	# Модуль для проверки стилей (Задание 4)
│       │   ├── income_tax.py	# Точка входа (Задание 1)
│       │   └── service.py	# Модуль для проверки зависимостей (Задание 2)
│       └── tests
│           └── test_bacic_income_tax.py
└── test.py
```

Что происходит под капотом

    Инициализация окружения: Система автоматически проверяет наличие виртуального окружения .venv. Если оно отсутствует, Make самостоятельно создаст его и установит необходимые пакеты из requirements.txt.
    Статический анализ (make typecheck): Проверка корректности аннотаций типов в модуле calc.py с помощью mypy.
    Контроль стиля (make lint): Комплексная проверка кода в example.py с использованием flake8 (стиль) и black (форматирование).
    Проверка зависимостей (make check-requirements): Запуск внешнего скрипта script.sh для верификации состава пакетов.

Точка входа

Для запуска комплексной проверки проекта не требуется вручную активировать виртуальное окружение или по отдельности вызывать линтеры. Все операции объединены в один высокоуровневый таргет:

```bash
cd testing/tdd
make check```
